# 真实环境联调记录

这份记录总结 2026-10-10 的真实模型网关、CubeSandbox v0.7.2 和 PostgreSQL 联调。具体地址、实例标识、组织信息和凭据不写入仓库；以部署环境自己的 `.env` 和脱敏测试报告为准。

## 已修复的应用问题

- **内网模型网关**：`LLM_ALLOW_HTTP=true` 才允许使用纯 HTTP。默认仍要求 HTTPS。
- **无 UCS 的封闭联调环境**：显式设置 `DEV_TOKEN` 可启用固定 Token 身份。Token 至少 16 字符，并始终具有管理员权限；启动时会记录 `auth_fixed_token_enabled` 告警。对外服务前应移除此配置并使用 UCS OIDC。
- **Cube 数据面 403**：Cube 只在创建响应中返回每实例 `trafficAccessToken`，连接接口不会重新签发。Harness 现在将 Token 和 Workspace 实例记录一起持久化，在每次远程命令中复用；清除实例状态时也会删除对应 Token。升级后缺少 Token 的旧实例会在持有租约时重建，保留原工作区卷。
- **快照恢复的挂载冲突**：快照模板已经保存 Volume 挂载，恢复时 Harness 不再重复声明挂载，避免 CubeMaster 拒绝创建。Cube 快照继承源卷挂载，因此当前拒绝跨工作区克隆，防止共享源工作区数据。

## 联调报告记录的环境问题

- **模板权限未满足要求**：执行用户虽然不是 root，但属于 root 组且可无密码 sudo。应重建模板，移除 root 组和 sudo 权限，再重跑原版验收探针。
- **S3 Volume 的 `O_TRUNC` 异常**：在已测 Cube 环境中，用 shell 重定向或 `open(path, 'w')` 覆盖较短内容会留下 NUL 填充。Harness 自身的文件写入使用临时文件加 rename；沙箱内其他程序的原地覆盖写仍受该存储缺陷影响，需要由 Cube 存储端修复并复测。
- **出口策略未生效**：`allowPublicTraffic=false` 没有阻止测试沙箱访问公网。该设置处理入站数据面授权；部署方仍需让 Cube 集群强制出口白名单，并在目标环境验证。
- **验收边界**：报告覆盖单节点集群。跨节点 Volume、一致调度、多节点运行、模板权限修复后的探针以及出口白名单强制后的复测尚未完成。

## 部署前检查

1. 使用真实 UCS OIDC；不要把固定 `DEV_TOKEN` 暴露给不可信客户端。
2. 给模型网关配置 HTTPS，并移除 `LLM_ALLOW_HTTP`。
3. 验收模板用户无 root 组和无密码 sudo 权限。
4. 验收所选 Volume 驱动的截断、持久化和重建行为。
5. 在 Cube 集群配置并验证出口白名单；`allowPublicTraffic=false` 本身不提供出口限制。
6. 根据集群 TTL、Worker 数量和容量策略验证暂停、恢复及资源对账。

报告记录的 Cube API 测试中，快照创建与恢复、工作区文件读写、暂停恢复、实例 Token 跨 Worker 重启复用和孤儿资源对账均通过；模板提权、`O_TRUNC` 和出口限制仍是未关闭项。报告没有验证多节点环境，也没有验证修复模板和网络策略后的最终状态。
