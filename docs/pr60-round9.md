# PR #60 第九轮：只读代理与 Memory 超时边界

基于 `4d2bb61` 修复工作区子管理器 Store 的重复包装，并明确验证 Memory 批处理
的超时语义。本轮无迁移，个人 schema 仍为 **v13**、共享 v6，Compose 仍为 6:13。

## 工作区只读检查

workspaceManager 已将 read 限定为 readMetadata、tx 限定为 workspaceTx。
构造子 SandboxManager 时显式传入工作区作用域，保留该代理，避免构造函数再次
把 read 覆盖为 workspaceTx。真正的租约获取/续期、容量和元数据变更继续使用写事务。

跨客户端 PostgreSQL 回归持有一个租约，让另一管理器等待并重复观察三次，再取得
租约执行 find；分别采集等待阶段和 owned/dispatch 的 SQL：

| 阶段 | SQL 数 | BEGIN | 加锁读取 |
| --- | ---: | ---: | ---: |
| 等待租约、观察元数据 | 8 | 0 | 0 |
| 单步 assertOwned、授权与 dispatch | 5 | 0 | 0 |

断言同时禁止 INSERT/UPDATE/DELETE、FOR UPDATE、FOR NO KEY UPDATE 和 FOR SHARE。
这是隔离的只读阶段，整次写入仍需要真实的状态事务。

同规模历史量下，原手动 Memory HTTP 回归成功/失败分别为 **120 / 84 条 SQL**，
返回 16,895 / 18,285 字节；上一轮为 190 / 144 条。这些数字为客户端 SQL 观测，
不代表数据库页读取量或生产 SLA。

## Memory 的共享 130 秒执行预算

整批 Memory 文件操作共用 withLease 的 **130,000ms 执行预算**，从沙箱准备完成、
执行回调开始计时；获取租约和远程准备另有原来的等待/远程超时约束。
本轮保留该总预算。maxFiles（可达 1,000）是存储容量上限，单次写入还受时间预算
约束；较大或较慢的合法集合可能返回 HTTP 504 / SANDBOX_REMOTE_TIMEOUT。
当前仍逐个读取主题，未提供批量文件元数据接口，不承诺任意容量都能在预算内修改。

新增三个虚拟时钟回归使用真实的 130 秒常量，覆盖：

1. 每步 30 秒、总计 120 秒：成功保存主题和索引，释放工作区锁，记录一次成功审计，
   130 秒定时器取消后不会误杀沙箱。
2. 每步正常返回需 50 秒，累计跨过 130 秒：返回 SANDBOX_REMOTE_TIMEOUT；
   故意延迟 kill 确认，让第三步读取在旧锁仍有效时正常返回。确认不会继续 dispatch
   主题或索引写入；清理确认后释放容量和锁，只记录失败审计。
3. 每步 40 秒，主题在 120 秒写入、索引仍在执行时达到 130 秒：失败并清理沙箱，
   在测试 Provider 模型下保留已写主题与旧索引，拒绝被清理实例上的迟到索引写入，
   不记录成功审计。

为制造迟到读取与清理重叠，第二项测试将清理等待设为 60 秒；生产默认清理预算
未调整，执行预算仍使用真实的 130 秒。

第二个场景还暴露并修复了迟到回调窗口：超时只丢弃 Promise，不会停止 SDK。
现在 withLease 在进入异步清理前标记回调失效，后续 owned 检查直接拒绝，避免在
等待 kill、原数据库租约仍存在时继续发出下一步远程调用。

文件与数据库审计仍不具备分布式事务原子性。已经发出的远程操作存在结果不确定性，
超时不承诺文件回滚；主题与索引可能部分更新。无法确认终止时继续沿用原来的
REMOTE_CANCEL_UNCONFIRMED 与 unknown 容量计费机制。

新增一项真实 PostgreSQL SQL 范围回归和三项虚拟时钟慢 Provider 回归。
本地完整强制验收 **341 通过、0 失败、0 跳过**；类型检查、构建、Demo 冒烟、
vendor、配置校验、Prettier、脚本语法及差异检查通过，npm audit 无 high/critical
（保留 2 moderate）。当前 CI 结果见 PR 描述。原权限复核、并发 Memory、租约 fencing、
Worker 停止及迟到清理回归一并运行。历史长测与第五轮维护扫描风险维持原标注。
